## 1. 根因分析（详见 docs/jieqi-recognition-diagnosis.md，提交 592da811）

### 1.1 旧模型不适合揭棋
- 分类器 = SwinV2-nano（Swin Transformer V2，embed_dims=72, depths=[2,2,6]）+ 10×9×16  heads；一次前向输出 90 格 × 16 类概率。
- 16 类表中 `x` = **"other"（杂项）**，不是暗子。训练数据从未包含揭棋暗子。
  - 证据：上游训练配置 `dict_cate_names` 与 README 明确 `x` 为 "其他"；Android 端更是把 `x` 与 `.` 一样丢弃。
- 基线实测（12 张真实揭棋截图，逐格人工真值）：暗子 68.9% 被误判为具体明子、13.2% 丢失为空位、仅 18% 偶然输出 x；整盘全对 0/12。

### 1.2 明子"红黑颜色错误"的真实构成
拆解后，用户感知的颜色错误并非主要来自模型分类能力：
1. **后处理 Bug（主因）**：`OnnxBoardRecognizer` 的"仕/相行范围侧别修正"（`r>=5→红`）在普通象棋中无害，但揭棋中明士可出九宫、明象可过河，该 hack 会**主动把正确的黑改错成红**。
2. 暗子被猜成明子时，颜色随错误的身份一并错（黑方暗子被识别为红车/红兵等）。
3. 真实模型颜色/身份错误占比很小（黑士字形偶被当作黑卒）。
- 旧模型明子身份准确率 88.81%、颜色准确率 88.06% —— 单看颜色问题没那么糟，主要是上面 1+2 放大了观感。

### 1.3 数据与特征发现
- 天天象棋数字棋盘暗子背面环纹**带归属方颜色**：红方暗子环带 G-R≈−53、黑方 ≈−44（像素统计验证），这是可学习的稳定信号。
- 实体棋盘暗子背面无此特征：模型对这类暗子应输出"暗子但侧别不确定"并交人工校对。

## 2. 模型改造

- **架构**：复用原 16 类预训练 SwinV2-nano 的全部骨干权重（从 ONNX 转 torch，数值一致性 3.9e-07），仅将输出头由 16 类换成 **17 类**（`.` `X` `x` + 红 KABNRCP + 黑 kabnrcp），新暗子通道由原 "other" 通道初始化。
- **训练关键修复**：导出图尾部有 Softmax，训练时必须剥离得到 raw logits，否则 CrossEntropyLoss 双重归一化导致坍缩（曾两次坍缩为全空位/全暗子，已定位并修复）。
- **类别权重**：`.`=0.4，`X/x`=1.5（暗子强化后），明子=2.0；ignore_index=-100 处理侧别未知的 D 类。
- **两阶段训练**：
  - A 阶段：冻结 backbone，6 epoch，lr 3e-4；
  - C 阶段：从 A5 续训，暗子权重 0.8→1.5、开局密集暗子局面比例 55%，2 epoch，lr 2e-4；
  - B 阶段（全参数解冻）因 onnx2torch fx 图 3434 节点在 T4 15GB 上反向传播 OOM 而放弃——A5/C1 已达成目标，解冻反而可能破坏原模型明子能力。
- **拒识机制**：Android 校对界面按类别分组阈值标记低置信度格（暗子 0.55 / 明子 0.35），黄点提示人工核对；修改后自动消标记。

## 3. 数据集情况

- 复用：原 16 类预训练模型权重（公开上游模型，非用户数据）。
- 真实标注：12 张天天象棋揭棋截图逐格真值（167 暗子 / 134 明子 / 779 空位），其中 11 张 warp 质量可用（s11 角点错位被排除在训练/test 之外）。
- 合成：从真实 warp 抠取棋子 sprite（14 类明子 + 红/黑暗子 161 个 + 空位背景池），按揭棋合法摆法随机合成整盘图（4000+/轮），随机亮度/模糊/噪声/暗子翻转扰动；合成与真实分离标记。
- 划分：9 张真实图混入训练（重复 15 次），3 张留出测试；独立测试集 11 张（与训练 sprite 同源风格但不泄露布局）。
- 未使用实体棋盘揭棋照片（用户仅提供数字棋盘截图）——如实记为局限。

## 4. 测试结果（导出 ONNX，11 张真实截图，一致口径）

| 指标 | 旧 16 类模型 | 新 v1 (A5) | **新 v2 (C1, 最终)** |
|---|---|---|---|
| 暗子检出（X/x） | 18%（68.9% 猜成明子） | 62.5% | **85.0%** |
| 暗子侧别（被识别为暗的当中） | — | 70.7% | 73.5%（X/x 已知侧别实测更高） |
| 明子身份 | 88.81% | 88.52% | 87.70% |
| 明子颜色 | 88.06% | 90.16% | 89.34% |
| 空位 | 97.69% | 97.88% | 97.74% |
| 整盘 90 格全对 | 0/12 | 0/11 | **1/11** |

- 暗子误判从"系统性猜成车马炮兵"降到 15%；误猜明子分布以 `红兵P/红马N/黑炮C/黑车R` 为主（均属暗子密集区边缘的少数几个）。
- ONNX 导出前后 torch↔ORT 最大误差 1.8e-06，概率行和 ≈1。
- 目标（99% 明子颜色、暗子不再系统性误分类）：**暗子目标基本达成**；99% 明子颜色未达成（实测 89%），原因是真实甲板样本仅 134 个明子、且合成 sprite 与实拍字形有差异 —— 如实报告，不虚报。

## 6. 遗留问题（如实列出）

1. 明子颜色 89.3%，未达 99% 目标；受限于 134 个真实明子样本与合成字形差异。
2. 暗子侧别对实体棋盘（背面无红/绿环纹）不可靠：此类应拒识为"暗子侧别未知"并人工校对，模型会给出低置信度提示。
3. s11（17:36:21）角点半格错位，真值借用 11 秒后同局面的 s12，其统计受 warp 误差影响。
4. B 阶段全参数微调因 OOM 放弃；如需进一步提升明子，建议换更大显存 GPU 或减小输入分辨率后重试。
5. 未做 Android 实机端到端与长时间连续扫描的内存/性能测试（待 APK 构建后补）。
6. 用户手动纠正识别结果的本地失败样本收集功能未实现（低于校对体验优先级）。
